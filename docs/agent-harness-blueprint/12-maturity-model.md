# 12. 成熟度模型

> 所属：Agent Harness 建设蓝图 / 第三部分 对照与采用
> 版本：v1.0-draft（2026-10-18）
> 用途：定位当前系统，而不是给系统贴标签。评分必须以证据为准。

## 1. 使用方式

1. 对十个维度分别定级；
2. 总体等级取“短板”，而不是平均分；
3. 有一票否决项时不进入更高等级；
4. 每次评估记录证据与日期；
5. 评审结论落到具体能力，而不是分数本身。

## 2. 十个维度

| 编号 | 维度 | 核心问题 |
|---|---|---|
| D1 | 控制循环 | 循环是否有界、可停止、可取消？ |
| D2 | 状态与持久化 | 崩溃后能否继续且不重复副作用？ |
| D3 | 工具与 ACI | 工具是否可控、可恢复、可评测？ |
| D4 | 上下文工程 | 预算内是否总是高信号？ |
| D5 | 权限与沙箱 | 危险动作能否在执行前被阻止？ |
| D6 | 记忆与知识 | 记住的是否正确、可找回、可遗忘？ |
| D7 | 模型网关 | 换模型是否只改变配置？ |
| D8 | 规划与多代理 | 拆分是否带来净收益？ |
| D9 | 协议与互操作 | 接入是否引入第二事实源？ |
| D10 | 评测与可观测性 | 能否证明变好、能否定位变坏？ |

## 3. 等级定义

| 等级 | 名称 | 总体特征 |
|---|---|---|
| L0 | 原型 | 单次调用或脚本拼接，无循环治理 |
| L1 | 可运行 | 有循环与工具，单进程内可完成任务 |
| L2 | 可恢复 | 有事实日志、检查点、工具终态、权限闸门 |
| L3 | 可运营 | 有观测、评测门禁、成本控制、沙箱分级 |
| L4 | 可扩展 | 有上下文工程、记忆固化、技能、子代理 |
| L5 | 自适应 | 契约稳定、可替换组件、策略即代码、持续演化 |

L2 是“能用于真实工作”的门槛；L3 是“能交给团队运维”的门槛；L4 是“能规模化扩展能力”的门槛。

## 4. 各维度分级描述

### D1 控制循环

| 等级 | 描述 |
|---|---|
| L0 | 单次模型调用，无循环 |
| L1 | `while` 循环，最多步数，能返回最终结果 |
| L2 | 停止条件覆盖完成/步数/取消/错误；工具调用有终态；取消可传播 |
| L3 | 预算（token/金额/时长）可执行；重试可中断；无进展检测 |
| L4 | 阶段化推进（规划/执行/验证）；上下文重置有交接包 |
| L5 | 循环策略可配置、可 A/B、可按任务类型自适应 |

### D2 状态与持久化

| 等级 | 描述 |
|---|---|
| L0 | 无状态，进程退出即丢失 |
| L1 | 内存消息数组；可能写文件日志 |
| L2 | 追加事件日志 + 确定性归约；检查点带身份与版本；恢复可对账 |
| L3 | 故障注入测试；租约 + fencing；恢复指标可观测 |
| L4 | 长任务分层存储；压缩/归档；跨设备或跨区域恢复 |
| L5 | 状态契约版本化并可迁移；多写者安全；可审计重放 |

### D3 工具与 ACI

| 等级 | 描述 |
|---|---|
| L0 | 直接函数调用，无 schema |
| L1 | 有工具描述与参数 schema；错误以字符串返回 |
| L2 | 严格 schema；结构化错误；副作用分类；超时与上限 |
| L3 | 只读并行、写串行；工具评测集；参数错误率可观测 |
| L4 | 工具按需裁剪；命名空间治理；MCP 工具统一契约 |
| L5 | 工具由评测驱动自动优化；描述与实现一致性强校验 |

### D4 上下文工程

| 等级 | 描述 |
|---|---|
| L0 | 全量拼接 |
| L1 | 简单截断或保留最近 N 条 |
| L2 | 有预算与压缩，按原子组处理，压缩必生成摘要 |
| L3 | 大结果卸载；缓存布局稳定；压缩前后指标可观测 |
| L4 | 渐进披露、按需检索、子代理隔离；上下文可回放 |
| L5 | 上下文策略按任务自适应；有 A/B 与成本-质量曲线 |

### D5 权限与沙箱

| 等级 | 描述 |
|---|---|
| L0 | 无限制执行 |
| L1 | 简单确认框；工具级允许/拒绝 |
| L2 | 策略判定 fail-closed；审批绑定动作指纹；基本沙箱 |
| L3 | 凭证隔离；沙箱分级；审计；注入用例 |
| L4 | 能力模型；代理凭证；子线程权限继承；红队演练 |
| L5 | 策略即代码、可验证；跨租户强隔离；形式化审计 |

### D6 记忆与知识

| 等级 | 描述 |
|---|---|
| L0 | 无记忆 |
| L1 | 全量历史或简单摘要 |
| L2 | 有长期存储与检索；作用域隔离 |
| L3 | 抽取与固化；冲突处理；来源与置信度 |
| L4 | 双时间/失效；遗忘与归档；多路召回与重排 |
| L5 | 记忆质量自评估；策略按场景选择；可解释可干预 |

### D7 模型网关

| 等级 | 描述 |
|---|---|
| L0 | 硬编码单一供应商 |
| L1 | 配置化模型与密钥；基本流式 |
| L2 | canonical 消息模型；流式装配状态机；错误归一 |
| L3 | 能力表被消费；重试安全判断；超时可配置；成本归因 |
| L4 | 路由与回退策略；缓存优化；多供应商一致性测试 |
| L5 | 按质量/成本/时延自动路由；在线评估驱动切换 |

### D8 规划与多代理

| 等级 | 描述 |
|---|---|
| L0 | 无规划 |
| L1 | 隐式计划，模型自行分解 |
| L2 | 显式待办/计划文件；子代理有独立上下文 |
| L3 | 子代理契约、预算、并发与取消；汇总可追溯 |
| L4 | 编排-工人/评估-优化等拓扑按任务选择；有对比基线 |
| L5 | 编排策略自适应；多代理成本-收益可预测 |

### D9 协议与互操作

| 等级 | 描述 |
|---|---|
| L0 | 全部私有实现 |
| L1 | 自定义 HTTP 接口 |
| L2 | 采用 MCP 接入工具，命名与信任有处理 |
| L3 | 协议版本固定；错误/超时/去重统一；有集成测试 |
| L4 | A2A/AG-UI 按需接入；状态权威清晰 |
| L5 | 多协议互通；可替换供应商；无锁定 |

### D10 评测与可观测性

| 等级 | 描述 |
|---|---|
| L0 | 无 |
| L1 | 打印日志，人工看 |
| L2 | 结构化追踪；基础指标 |
| L3 | 内部金标集 + 回归门禁；成本与安全指标 |
| L4 | 轨迹评测；灰度与回滚；OTel 语义约定 |
| L5 | 在线评估与自动优化闭环；指标驱动架构决策 |

## 5. 一票否决项

以下任一项为“否”，总体等级不得高于 L2：

- [ ] 工具调用没有唯一终态；
- [ ] 恢复可能重复不可逆副作用；
- [ ] 权限判定可被绕过，或默认 fail-open；
- [ ] 日志不是唯一事实源，存在双写；
- [ ] 取消不能传播到执行进程。

以下任一项为“否”，总体等级不得高于 L3：

- [ ] 没有内部评测集与回归门禁；
- [ ] 成本无法按 run 归因；
- [ ] 凭证与执行环境未隔离；
- [ ] 上下文超限时无策略（静默丢弃或直接失败）。

## 6. 评分卡模板

```yaml
assessment:
  system: <名称>
  date: <日期>
  evaluator: <人>
  dimensions:
    D1: {level: 2, evidence: "..."}
    D2: {level: 3, evidence: "..."}
    ...
  vetoes:
    tool_terminal_state: true
    no_duplicate_side_effects: false
    ...
  overall:
    short_board: 2
    gates_passed: 3
    final: 2
  top_gaps:
    - dimension: D2
      gap: "缺少 fencing"
      severity: high
      next: "..."
```

`short_board` 是十维最小值；`gates_passed` 是满足一票否决的最高等级；`final` 取两者较小值。

## 7. 评分证据要求

每个等级必须附至少一条可验证证据：

| 证据类型 | 示例 |
|---|---|
| 代码位置 | `file:line` |
| 测试 | 用例名与运行结果 |
| 配置 | 结构化配置片段 |
| 生产数据 | 指标、追踪样本 |
| 文档 | 明确的设计声明（不能替代实现） |
| 演练 | 故障注入、红队报告 |

“我们计划做”不是证据。未实现的声明只能算作差距，不能算作等级。

## 8. 等级与投入的关系

| 等级 | 典型投入 | 收益 |
|---|---|---|
| L1 → L2 | 中：状态模型、事务、权限 | 可处理真实任务 |
| L2 → L3 | 中高：观测、评测、成本 | 可交给团队运维 |
| L3 → L4 | 高：上下文、记忆、子代理 | 能力可扩展 |
| L4 → L5 | 很高：平台化、策略化 | 可持续演化 |

不要跳级。没有 L2 的恢复能力，L4 的多代理只会放大故障。

## 9. 常见误判

| 误判 | 纠正 |
|---|---|
| 有向量库就是有记忆 | 记忆看写入、冲突、遗忘，不看存储 |
| 有多代理就是先进 | 看是否有净收益与成本数据 |
| 有 trace 就是可观测 | 看是否能定位到步骤与工具 |
| 用了框架就有架构 | 框架不替你定义契约与不变量 |
| 有测试就是有质量 | 看测试是否覆盖故障与轨迹 |
| 文档写了就是实现了 | 以代码与运行证据为准 |
