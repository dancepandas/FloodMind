# ADR-008：协议引入范围（MCP 仅工具，不引入 A2A / AG-UI）

- 状态：已接受
- 日期：2026-10-18
- 关联：`docs/agent-harness-blueprint/09-protocols-and-interop.md`、`13-floodmind-gap-analysis.md`（G-21）、`14-adoption-roadmap.md`（ADR-08）

## 背景

FloodMind 的集成边界是 Python SDK：宿主进程注入 `ModelClient`、工具、Skill 与 Workspace，任务身份、审批与执行事实都落在本进程的 Canonical Journal 内。蓝图阶段 E 列出 A2A（跨组织代理协作）与 AG-UI（第三方前端协议）作为候选扩展，但要求有明确需求与收益证据后再引入。

当前没有跨组织调用需求；前端由宿主自行消费 `Agent.stream()` 事件与 `events_after(sequence)` 回放，不需要通用协议层。进程内委派已有 `SubAgent` / `ParallelTask`，缺口是收益证据而非协议。

## 决策

1. MCP 只用于工具接入，不作为 Agent 间协作协议。
2. 不实现 A2A 端点、代理卡与跨进程任务协议。
3. 不实现 AG-UI 端点与前端协议适配层。
4. 不为上述能力预留抽象、配置开关或占位模块。

## 理由

- A2A 会把任务身份、权限与运行事实分散到外部代理，与「Canonical Journal 是唯一运行事实源」「身份层级唯一」的不变量冲突。
- AG-UI 事件是投影而非事实源；提前实现会锁死事件形状，并让宿主的展示需求下沉到 runtime，形成双维护。
- 两者都属于宿主或跨组织边界，当前没有第二个实现方，提前建设只会增加序列化、版本协商与安全审计成本。

## 后果

- 第三方接入需通过 Python SDK 嵌入或由宿主自行适配；这是当前的明确取舍。
- 若未来引入，必须先补齐：任务包与返回契约、跨边界审批与取消传播、事实源合并规则、事件映射与版本协商。
- 新增依赖前先更新本 ADR 与架构基线，不在代码中留下未使用的协议抽象。

## 重新评估的触发条件

满足任一条件时重新评估：

- 外部组织或异构运行时需要把任务作为独立 Agent 调用，且无法通过 SDK 嵌入；
- 出现多个独立前端要求同一套接口，逐一适配成本高于统一协议；
- 跨信任边界传递任务、产物与审批指纹的需求，现有 Journal / 审批模型无法表达；
- AG-UI 或 A2A 规范稳定并提供可验证的一致性测试。

## 备选方案

| 方案 | 未采用的原因 |
|---|---|
| 立即实现 A2A + AG-UI | 无外部调用方，无法验证收益，且与唯一事实源约束冲突 |
| 只实现 AG-UI 适配层 | 当前前端可直接消费 SDK 事件，适配层没有消费者 |
| 预留协议抽象层 | 违反「不预先建设」，会形成无测试覆盖的死代码 |
