## 权威与冲突处理

1. 已接受的架构决策及本目录/测试目录的现行契约表达开发约束。
2. 源码与可重复测试是当前实际行为的证据；若与约束冲突，不得假装已实现。先记录差异，明确本次修实现还是修文档，再以测试证明。
3. `DEVELOPER_GUIDE.md` 是使用教程，不能覆盖现行契约。
4. 知识图谱描述结构，不替代行为契约；历史计划、研究和评估不作为当前 API 承诺。

每份新契约必须写清：范围、最小正确例、框架保证、开发者责任、顺序/生命周期、失败/取消/并发语义、禁止模式、变更消费者和验收证据。不允许用目标设计冒充现有保证。

内核/事件、状态/恢复、插件生命周期、Provider/Skill/MCP 专项契约尚未交付。它们需要独立追踪源码与调用者后编写，不能从某个方法存在就推断生命周期保证。
